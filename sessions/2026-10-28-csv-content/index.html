    2026-10-28 · Content in CSV and session-start context¶

    Duration: afternoon Commits: 1cacece feat: author cards, enemies, relics and events from CSV · 3132230 docs: capture the radial map and read the full context at session start · this commit — skills: three design skills for the effect batch

    Objective¶

    Two things that looked separate and are not:

    1. Take content out of the code. Adding a card cannot mean creating a ScriptableObject by hand; it should mean writing a row in a spreadsheet.
    2. Not losing context between sessions. The agent only read the newest note, and the Pending items from three sessions ago were never seen.

    What was done¶

    Content pipeline¶

    • Csv.cs — CSV reader and writer with automatic delimiter detection (; for Excel in Catalan/Spanish, , otherwise) and keeping the same delimiter when saving.
    • ContentCsv.cs — the format in a single place: headers with aliases, validation with row numbers, writing and reading the four tables. It is the only definition of the format; neither the runtime nor the editor keeps a copy.
    • ContentDatabase.cs — loading from Resources/Content, cache and Reload(). It is needed because the project has domain reload disabled: GameManager.StartNewRun calls it so a CSV edit shows up without restarting Play.
    • Flat data — CardData and EnemyData stop being ScriptableObject and become [Serializable], so they can be validated outside Unity. RelicData and EventData are added, still without a game system.
    • copies — new column to preserve the starting deck of 4 Strike / 4 Defend.
    • Effects in one cell — damage:8|vulnerable:2, with the card text auto-generated when the text column is empty.
    • Facades — CardLibrary and EnemyLibrary keep the API the game already used (Normal, Pack, Boss(rng)) but read from the CSV.
    • Editor window — Prototype → Content (CSV): tabs per table, add, copy and delete rows, reload, save and validate. It warns if the file changed outside and marks the relic and event tables as inert.
    • tools/content-check — validation and round-trip of the CSVs with dotnet run, without opening Unity. tools/compile-check.ps1 now compiles Assets/Editor too.

    Documentation and context¶

    • docs/content.md — the format, the effects, the aliases and the workflow.
    • Radial map capture at docs/images/2026-10-28-radial-map.png, inside the morning page.
    • AGENTS.md — the start routine no longer reads only the latest note: it reads index, roadmap, architecture, content, the session index, the three latest notes in full, the Pending sections of every old one and the git log. The reply must quote the pending items, not reconstruct them from memory, and must say so if the roadmap and the latest note contradict each other.

    Verification¶

    • powershell -ExecutionPolicy Bypass -File tools/compile-check.ps1 → 0 errors, 0 warnings.
    • dotnet run --project tools/content-check → 10 cards, 5 enemies, 0 relics, 0 events and Content OK. Error test done: it prints the row and exits with code 1.
    • Unity, Play mode: Deck 9 cards, Rooms 1/65, HP 72/72 and no errors in the fresh console. The 9 cards confirm that copies and loading from the CSV work.
    • python -m mkdocs build --strict → no errors.

    Decisions¶

    • The CSV is the single source of truth. No .asset files are generated: what is in the spreadsheet is what the game loads, and the Editor window saves to the same file.
    • Flat classes instead of ScriptableObject. They allow validating and round-tripping with dotnet, outside Unity, inside the same repository.
    • The delimiter is detected and preserved. A file saved by Excel in Catalan must not become a comma-separated file that breaks decimal numbers.
    • Effects live in one cell. One column per effect would have made the table grow without limit; the card text generates itself when it is not there.
    • Relics and events exist as a catalogue, not as a system. It is better to have the tables and the editor ready before the code that uses them; the window says so explicitly to avoid selling smoke.
    • The session start reads the whole context. The cost is a bit of reading; the cost of the alternative is repeating work or contradicting a decision from three sessions ago.
