    2026-10-27 · Skills externes des de skills.sh¶

    Durada: tarda Commits: 3183de6 — skills: nou skills vendoritzades del catàleg de skills.sh

    Objectiu¶

    Deixar d'escriure les skills a mà. El coneixement d'enginyeria i de disseny que fem servir cada sessió (uGUI, cicle de vida de MonoBehaviour, Input System, zones de cartes, economia d'una run) no és nostre: existeix en catàlegs públics d'agent skills. La feina d'avui és portar-lo de fora, versionat al repo, en lloc d'anar-lo reinventant.

    Mètode: com es troben i s'instal·len¶

    1. La API queda tancada. https://skills.sh/api/v1/skills/search?q=... retorna 401 authentication_required: vol un token OIDC de Vercel. No és una opció per a un projecte local.
    2. El cercador web sí que serveix. Les pàgines https://www.skills.sh/search?q=<terme> es renderitzen al servidor: obrint-les amb el navegador s'hi llegeix la llista sencera (skill, repo, instal·lacions). Les fitxes https://www.skills.sh/<owner>/<repo>/<slug> porten la comanda d'instal·lació i els audits de seguretat.
    3. Instal·lació vendoritzada. En lloc de npx skills add (que escriu a la carpeta global de l'agent i no queda al repo), es baixa l'upstream i es copia a .opencode/skills/<slug>/, amb un peu Upstream source.

    El cercle complet, per repetir-lo quan calgui actualitzar o afegir una skill:

    # 1. Trobar el camí real dins el repo (les rutes varien: skills/, skills/unity/, SKILL.md a l'arrel)
Invoke-RestMethod "https://api.github.com/repos/<owner>/<repo>/git/trees/main?recursive=1" |
  Select-Object -ExpandProperty tree | Where-Object { $_.path -like "*SKILL.md" }

# 2. Baixar el SKILL.md i els fitxers que referenciï (references/, scripts/)
Invoke-WebRequest "https://raw.githubusercontent.com/<owner>/<repo>/main/<ruta>/SKILL.md" `
  -OutFile ".opencode/skills/<slug>/SKILL.md" -UseBasicParsing

    Decisions¶

    • Vendoritzar, no instal·lar globalment. El repo és el que ha de saber amb què treballa; una instal·lació global no viatja entre màquines ni queda a l'historial.
    • El cos és de l'upstream. Només s'hi afegeix el peu de procedència (repo, ruta, data, audits) i, si cal, la normalització d'una description trencada. Les diferències amb el projecte es documenten a la skill pròpia, no editant l'externa.
    • Quan xoquen, mana la pròpia. unity-ugui-code sap que la UI es construeix per codi i a 1600×900; ui-ugui assumeix prefabs i Editor. Les externes són doctrina general.
    • Cercar fora és el pas 1. La rutina de final de sessió d'AGENTS.md ara diu, en aquest ordre: buscar a skills.sh el coneixement general dels propers 1-2 punts del roadmap; escriure una skill pròpia només pel que l'upstream no pot saber (números, classes, paranys i verificació d'aquest repo); i actualitzar les existents si la sessió ha canviat com funcionen.
